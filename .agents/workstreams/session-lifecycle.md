- Host evidence (installed `@deepseek-ai/dsh@0.2.2-rc.3` in `app.asar`): `dsh-session/src/known-event-types.ts` lists `todo/write`, `goal/change`, `approval/asked`, `approval/decided`. `todo/write` is a whole-list snapshot `{ todos: Array<{ content, status: 'pending'|'in_progress'|'completed' }> }` with no id and no cancelled/paused status; removal from the list is the only cancellation signal and `in_progress → pending` the only pause signal. `goal/change` is a full snapshot with `operation: 'create'|'edit'|'pause'|'resume'|'complete'|'block'|'clear'` and a `goal` snapshot (`phase: 'active'|'paused'|'blocked'|'complete'`, `blockedReason?`) or a clear tombstone. `approval/asked` carries `{ id, toolName, callId?, reason? }`; `ApprovalService.request()` appends it at `dsh-user-approval/src/index.ts:252` before `decide()` (the waterfall) at `:258`, and session append notifies `session/event` observers synchronously, so listeners see `asked` before any answerer. No `survey` event exists: `ask_user_question` is `dsh-tool-ask-user` → `ctx.userQuestions.ask()` → `user-questions/request` waterfall; this workstream observes only `tool/call`/`tool/result` and never hooks the waterfall.
- Adversarial review: Verified the three failure modes from real host behavior. (1) **False-positive waiting**: `policy='never'`/aborted asks append `asked` then `decided` immediately, and an `ask_user_question` that returns without waiting appends `tool/call` then `tool/result`; both are suppressed by a cancellable 1500 ms settle keyed by approval id / survey callId, with id-less legacy approvals kept immediate and `dispose` flushing real waits. (2) **Missing/corrupt payloads**: `todo/write`/`goal/change` validate every field; malformed snapshots warn and do not advance state, so a later valid snapshot still computes the correct diff. (3) **Duplicates**: session-seq dedup for todo/goal, goal revision dedup for replayed snapshots, approval `seq+hash(detail)` and survey callId dedup; `todo/write` is diffed against bounded per-session state so a replay produces no second transition. Also checked category gating: the event layer keeps only the existing `events.*` switches and leaves delivery defaults to the notify-side session-notification matrix (single authority); action cards are minted only after `notifyAll` settles and only when `canSendRemote(meta) !== false` and `outcome.suppressed` is empty (legacy notifiers without `canSendRemote` keep the old synchronous path).
- Handoff: Added `src/host/lifecycle.mjs` (normalize/diff todo snapshots, map goal operations to categories, generic `ask_user_question` survey intent, zh/en copy, bounded session/revision state) and wired it into `src/event-listener.mjs`: todo/goal/survey intents, `sessionId`/`sessionTitle`/`category` in the `notifyAll` second argument, `wiring.sessionTitleOf(session)` with `session.title`/`header.title`/null fallback, approval/survey settle queue, and the `canSendRemote` + `result.suppressed` action-card gate. Category mapping: todo completed/cancelled/changed/paused; goal complete/clear/pause(+block)/create+edit+resume; baseline `session.started/completed/error/cancelled/status/approval`. `test/session-lifecycle-notifications.test.mjs` (18 tests) covers payload validation, diff semantics, malformed input, replay dedup, both settle windows, dispose flush, and the card gate; `test/wiring.route.test.mjs` expectations now include trusted session metadata.

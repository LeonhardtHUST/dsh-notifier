- Host evidence (installed `@deepseek-ai/dsh@0.2.2-rc.3` in `app.asar`): `dsh-session/src/known-event-types.ts` lists `todo/write`, `goal/change`, `approval/asked`, `approval/decided`. `todo/write` is a whole-list snapshot `{ todos: Array<{ content, status: 'pending'|'in_progress'|'completed' }> }` with no id and no cancelled/paused status; removal from the list is the only cancellation signal and `in_progress → pending` the only pause signal. `goal/change` is a full snapshot with `operation: 'create'|'edit'|'pause'|'resume'|'complete'|'block'|'clear'` and a `goal` snapshot (`phase: 'active'|'paused'|'blocked'|'complete'`, `blockedReason?`) or a clear tombstone. `approval/asked` carries `{ id, toolName, callId?, reason? }`; `ApprovalService.request()` appends it at `dsh-user-approval/src/index.ts:252` before `decide()` (the waterfall) at `:258`, and session append notifies `session/event` observers synchronously, so listeners see `asked` before any answerer. No `survey` event exists: `ask_user_question` is `dsh-tool-ask-user` → `ctx.userQuestions.ask()` → `user-questions/request` waterfall; this workstream observes only `tool/call`/`tool/result` and never hooks the waterfall.
- Adversarial review: Verified the failure modes from real host behavior. (1) **False-positive waiting**: `policy='never'`/aborted asks append `asked` then `decided` immediately; both suppressed by a cancellable 1500 ms settle keyed by approval id, with id-less legacy approvals kept immediate and `dispose` flushing real waits. (2) **False-negative timed question**: rc.3 timed `ask_user_question` returns `{ pending: true, callId, message }` as JSON text in `tool/result` (`dsh-tool-ask-user/src/timed.ts:195-203`); the host's own `dsh-user-questions/src/projection.ts:isPendingResult` treats `pending === true` as still answerable, and `error.code === 'TOOL_OUTCOME_UNKNOWN'` likewise. Our detection mirrors that (no callId comparison, no `isError` override), so the short-delay reminder is kept; a later `user/message` with `source.kind='user-question-reply'` cancels it, while ordinary `{answers:[…]}` / other errors / unparseable results cancel. A quick no-wait `tool/result` still cancels. (3) **Missing/corrupt payloads**: `todo/write`/`goal/change` validate every field; malformed snapshots warn and do not advance state, so a later valid snapshot still computes the correct diff. (4) **Duplicates**: session-seq dedup for todo/goal, goal revision dedup for replayed snapshots, approval `seq+hash(detail)` and survey callId dedup. Also checked category gating: the event layer keeps only the existing `events.*` switches and leaves delivery defaults to the notify-side session-notification matrix (single authority); action cards are minted only after `notifyAll` settles and only when `canSendRemote(meta) !== false` and `outcome.suppressed` is empty (legacy notifiers without `canSendRemote` keep the old synchronous path). Optional `wiring.ownsRemoteAttention(intent, session)` is consulted only for `session.approval`/`session.survey` (true → `localOnly: true`); absent/false/throwing values keep the normal route, so a missing host route can never suppress a notification.
